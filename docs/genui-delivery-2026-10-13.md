## Contract and safety boundaries

Shared pure parser/schema:
`/Users/devgwardo/hermes-desk/electron/local/mcp/genui.mjs`, with a `.d.mts`
declaration and frontend imports through `src/lib/genui/index.ts`. It is ESM
bundled by Vite and synchronously required by this Electron's Node 22.
Typecheck, production build and direct Electron Node compatibility checks pass.
An actual Electron Node probe also loads the CJS dispatch/catalog and the ESM
validator from a temporary ASAR archive. This proves that import seam, not a
signed or fully packaged app acceptance run.
The standalone unpacked `.cjs` shim also carries the strict schema/parser inline,
without a sibling-module or dependency assumption. Regression tests compare its
schema and validation decisions with the shared contract and execute the copied
shim alone under Node and Electron. Both catalogs require exactly the original
ten browser definitions plus `render_ui`, rejecting missing, extra and duplicate
names, **any changed browser definition/schema**, and mutated render schemas.
The standalone fallback now exactly matches the canonical ten definitions,
including descriptions, property types, enums, defaults and required arguments.
Changed live/sibling browser catalogs are discarded, not admitted as authority.

`render_ui` accepts:

```json
{
  "version": 1,
  "components": [
    { "type": "stat", "title": "Agent estimate", "value": "12" },
    { "type": "table", "title": "Queue", "columns": ["Task", "Count"], "rows": [["Review", 3]] },
    { "type": "bar_chart", "title": "Work", "items": [{ "label": "Review", "value": 3 }], "unit": "tasks" },
    { "type": "checklist", "title": "Next", "items": [{ "id": "review", "label": "Review the draft", "checked": false }] }
  ]
}
```

- At most 4 components per call; at most 4 full specs per chat message/room turn.
  Renderer scans at most 128 historical events and deduplicates by stable call ID.
- Total serialized spec: 16,384 UTF-8 bytes. Titles 80 characters. Stat values 80,
  optional detail 160. Table: 6 columns, 20 rows, rectangular, cells 160
  characters or finite numbers in `[-1e12, 1e12]`. Column names 60 characters.
  Chart: 12 items, labels 80, finite values `[0, 1e12]`, optional unit 40.
  Checklist: 20 items, unique alphanumeric/underscore/hyphen IDs up to 40,
  labels 160, optional boolean initial checked state.
- Unknown keys/types, inherited/prototype/getter objects, malformed JSON,
  nonfinite values, sparse arrays, ragged tables and duplicate checklist IDs
  are rejected. Text excludes markup delimiters, executable/remote URI schemes
  and Unicode control/format/bidi/line-separator characters. Strings render only
  as React text. URI checks have a word boundary so `Profile:` and `Metadata:`
  are ordinary labels rather than false-positive schemes.
- No model-supplied HTML, JS, CSS, links, resources, IPC or filesystem actions.
  The only generated inline style is an internally calculated, bounded chart
  percentage. No added packages/assets/fonts and no general chat redesign.
- MCP dispatch uses the existing explicit enabled-profile gate, authenticated
  socket, lane stop/pause fence, queue, timeout, argument/resource bounds,
  cancellation and audit path. A data render returns before tab lookup/opening
  or browser executor `run`; the old browser action allowlist is unchanged.
- Successful result is dual-emitted as MCP text JSON and `structuredContent`:
  `{ "genui": <validated spec>, "genuiOccurrence": <server-issued UUID v4> }`.
  The UUID is minted only after dispatch admission, not accepted in model input.
  Failed/cancelled/error envelopes never produce
  display metadata. Full data is separate from the unchanged small raw-activity
  display caps; argument-text display is also capped at 300 characters.

## Transport, storage and interaction

Live DM `tool.complete` consumes the full raw result, not truncated result text.
Only exact canonical/namespaced Hermes Desk render tool names qualify.
Replacements are by call ID; failing/running replacement removes display data.
When an envelope or durable result row declares a status, only known successful
terminal statuses qualify; pending/running/timeout, unknown and failed statuses
cannot authorize metadata even if they contain a valid-looking data spec.
Actual backend history reconstruction requires an assistant tool call paired
with a successful tool result by ID; arguments, running calls, failed results
and unpaired/name-only render results do not authorize a widget.
Current installed Hermes projects raw history down to user/tool-name/final-text
rows, discarding results. The adapter supplements only qualifying render rows
through the already-allowlisted, authenticated, profile-scoped session export.
The raw successful call/result pair must belong to the **same durable user row**;
display text/order remain authoritative. A matching-source persisted
`untrusted_tool_result` wrapper may be decoded; mismatched sources and failures
remain omitted. Limits: 8 MiB UTF-8 response, 20,000 scanned rows, ten-second
deadline. Unavailable/oversized/malformed exports fail closed, leaving ordinary
chat text intact. Synthesized assistant keys include prompt and call ownership,
avoiding collision with actual database row IDs.

Room output now retains validated full metadata on the owning running turn and
its final message. Tool-only successful turns produce a final room message.
Existing native atomic room checkpoints retain that data; room projections
revalidate it before display. Closed/retired/cancelled member callbacks continue
to be fenced; retries clear previous generated output.
Terminal recovery now folds preceding render lifecycle events through the same
sequence-/member-/session-fenced reducer before settling authoritative final text.
It does not replay text deltas, resubmit prompts, or accept post-terminal results.
Closed sessions and terminal cancellation/error still discard output.

Both classic and messenger transcripts render widgets, including tool-only
bubbles. Each generated block is labeled **Generated UI · Agent-provided data, not verified**.
Data is not verified telemetry/billing and never app/security authority.
Checkboxes use native accessible inputs; tables have keyboard-focusable regions,
semantic headers and bounded wrapping. Bar charts also expose labels/numbers
as accessible text.
Fractional bars normalize against their real maximum; all-zero charts remain
zero-width. A native geometry regression prevents the generic messenger
form-control minimum from enlarging checkboxes and misaligning labels.

Checkbox clicks have no backend callback/import. Notes use one app-origin
localStorage record, scoped by conversation + speaker profile + call ID +
**server-issued durable occurrence** + component index, with exact full spec
revision matching. The same occurrence survives live metadata, raw history,
lossy-history supplementation, room turns/final messages, projections and native
checkpoints; it is never minted by a renderer or inferred from provider call ID.
Legacy/invalid-occurrence rows render and interact in memory only, without reading
or writing shared persistent notes. Any change in that
spec resets its notes. Limits: **32 checklist entries total, 131,072 UTF-8
bytes, at most 20 checked IDs per entry, seven-day expiry from the last local
write**, oldest-first eviction. Storage errors/corruption fall back to local
in-memory interaction. This local note cache is not transcript durability;
actual data durability uses backend raw tool history or the native room journal.
No cross-device synchronization or guaranteed notes retention across a changed
app origin, storage clear, TTL/eviction, or payload revision.
