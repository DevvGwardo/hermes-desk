| SA-01 / HD-06 / J2 | Arbitrary **same-UID code remains trusted**. It can read profile YAML, app credentials, shim environment, browser partitions and main-process memory where OS access permits. Profile tokens prevent unauthenticated/cross-profile confusion but are not an OS identity boundary. | SA-03 / J3 | `discoverHermes`/bin-guard check a resolved final regular file and group/world write bits, not launcher identity, owner, writable ancestors, Python/shebang/dependency integrity or check-to-exec identity. | SA-05 / D4 | YAML and credential-store publication are two atomic renames, not one transaction. A failure between them can leave a new config without matching authority. | SA-06 / J6 | Text in canvas/images/video, CSS-generated content and arbitrary visually rendered/non-AX content has no reliable token/credential detector. The pure redactor has no closed-shadow-root relation; production CDP may expose some roots, but complete cross-runtime coverage is not established. Patternless passwords/OTP prose and fragmented, reordered, unrelated, more-than-four-node or over-8-KiB-per-fragment echoes can evade heuristics. | Accept the heuristic boundary or block risky screenshot/content surfaces pending a reliable detector. OCR would not be a perfect security boundary and was not added. |
| SA-07 / HD-01 / J6 | Native AX returns bullets for password inputs. An arbitrary **user-entered, unapproved** password echoed elsewhere cannot necessarily be learned from that source field. Restrict sensitive browsing/agent sharing or implement a trustworthy main-only value source before accepting this case. |
| SA-08 / HD-03 / J4 | Screenshot stability checks refuse observable content/geometry changes and animation starts, but are not an atomic renderer-frame security primitive. JPEG is lossy: exact black is asserted before encoding; returned JPEG interiors allow channel values 0–3. | Accept the bounded DOM/AX stability model or require a stronger atomic snapshot/masking primitive. Do not equate the 31-region corpus with proof against adversarial pixels. |
| SA-09 / HD-04 / C8 | Effective click/Enter/Space checks refresh semantics and default-deny detected transactions, but label/URL/form heuristics do not classify every consequential page action (custom controls, drag, scripts, unexpected input effects). Per-agent policy configurability is a separate backlog item. | Accept bounded browser authority and supervise real-account actions, or require stronger per-site/action permissions. |
| SA-10 / HD-05 | Agent browser sessions now use a fail-closed connection-time proxy: all DNS answers must be public and the dialer receives a validated literal IP. These controls do not sandbox arbitrary local tools or upstream computer-use networking. | Review `../RED_TEAM_REMEDIATION_RT01_RT07.md` and the deliberate public-web-only/isolated-session compatibility changes. No owner acceptance or general same-UID isolation is implied. |
| SA-11 / C9 / HD-07 | A timed-out/cancelled command is not a rollback. The watchdog requests close and removes its tab after a two-second grace period, or quarantines its lane on failure. It cannot kill arbitrary JS dependencies, undo already-submitted actions, interrupt a blocked main event loop, or bound every V8/kernel/CDP/image allocation. Teardown can lose unsaved tab state. | Accept destructive timeout recovery and bounded application-level budgets; isolate processes if stronger execution/memory termination is needed. |
| SA-12 / persistence | Browser profiles persist cookies/storage. Workspace metadata, audit origins/profile IDs and app diagnostics are local private data, not anonymized data. Page titles/URL paths may echo unapproved arbitrary secrets despite query/fragment stripping and approved-value scrubbing. Private screenshots/transcripts are not persisted by this browser route, but Hermes may persist tool history/CUA captures. | Review local retention/backup/access policy and do not make a general “nothing secret reaches disk” claim. |
| SA-13 / host/HUD | The sandboxed web tab is a separate boundary from the privileged app bridge, HUD and native computer actions. Renderer RPC allowlists/consent are repaired, but a trusted main renderer and installed local tools still have significant user authority. Ad-hoc signing supplies no Developer ID provenance and can reset TCC grants. | Review native IPC/TCC scope and choose signing/distribution policy before installation; no signing or TCC decision was made here. |
